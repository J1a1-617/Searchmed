## Design

- Source cases: `case_15_node_2`, `case_16_node_2`.
- Same API key, model `gpt-5.5`, Qwen3-Reranker-4B, BGE dense index, top-k 8, two retrieval steps, one worker, and the same benchmark inputs.
- A used the archived pre-change agent at `/home/visitor/yangijiayi/skill_runs/skill_mount_ab_20260902`.

The eager B implementation did not improve the binary score because `gpt-5.5` completed the old single-call schemas. It added five calls and approximately 0.8% total tokens, while reducing aggregate agent time by about 13.3%; the time gain came mainly from Safety prefiltering in `case_15_node_2`, not from unconditional partitioning.

M5 grade-tolerance accuracy was 1.0 for A and 0.5 for B, but it is not the requested primary score and the two-case sample is too small for a general claim.

## Decision

Keep deterministic Safety claim prefiltering and EvidenceReview omission of rejected/insufficient rows. Change the truncation skill from eager item-count partitioning to adaptive recovery:

1. Attempt one complete structured result first.
2. Only if function arguments are incomplete/invalid or structured semantic validation fails, split the repeated evidence/claim items into bounded complete calls.
3. Do not activate on network, authentication, or unavailable-model errors.
4. Merge and validate stable IDs after all recovery parts.

This retains the original truncation remedy without imposing extra calls on stages that the active model can complete. A follow-up B run on the same two cases is required after the adaptive revision.
